# Traefik Configuration Provider from systemd

![Build status](https://codeberg.org/giggio/systemd_traefik_configuration_provider/badges/workflows/build.yaml/badge.svg)

Main repo: [codeberg.org/giggio/systemd_traefik_configuration_provider](https://codeberg.org/giggio/systemd_traefik_configuration_provider)

This app will gather info from systemd and publish it as YAML configuration in the
[Traefik format](https://doc.traefik.io/traefik/reference/routing-configuration/other-providers/file/).

## Quick Start

Create a systemd service annotated with Traefik configuration. This is using the
same style as the
[Docker configuration](https://doc.traefik.io/traefik/reference/install-configuration/providers/docker/).

You can use the example sleep service at [./test/sleep.service](./test/sleep.service).
Clone this repo, `cd` to it, then:

```bash
# copy the service
sudo cp test/sleep.service /etc/systemd/system/sleep.service
# reload the systemd daemon
sudo systemctl daemon-reload
# test the service
sudo systemctl start sleep
sudo systemctl status sleep
```

Run the application with cargo:

```bash
TRAEFIK_OUT_DIR=`pwd`/test/units/ RUST_LOG=systemd_traefik_configuration_provider=trace cargo run
```

Files will be generated at the `TRAEFIK_OUT_DIR` environment variable location. If not set, they will output to:
`/etc/traefik/dynamic/units`.

## How it works

Only `.service` units are considered. A unit is tracked when its unit file or one of its drop-ins has an `[X-Traefik]`
section. Each `Label=` in that section is a Traefik label, in the same format used by the Docker provider. A leading
`traefik.` is removed, the rest becomes the YAML tree (`a.b[0].c=value` works as it does in Docker labels).

For every tracked unit that is running there is a `<unit name>.yml` file in the output directory, and it is removed
when the unit stops. The files are updated when:

* a unit starts or stops;
* a new unit shows up (e.g. it was just installed);
* systemd is reloaded (`systemctl daemon-reload`, or a `nixos-rebuild switch`). Units that got or lost an
  `[X-Traefik]` section are tracked or dropped, and changed labels are written.

Files are replaced atomically, so Traefik never reads a half written file.

Every generated file starts with this line:

```yaml
# Generated by systemd_traefik_configuration_provider, do not edit.
```

On startup, files with that line that do not belong to a tracked unit are removed (e.g. a unit that was removed while
the application was not running). Files without it are never touched, so the output directory can be shared with other
Traefik dynamic configuration. Files created by versions before this line was added are not removed, delete the orphans
by hand once.

## Options

| Option | Environment variable | Description |
| --- | --- | --- |
| `-t`, `--traefik-out-dir <DIR>` | `TRAEFIK_OUT_DIR` | Output directory. Default: `/etc/traefik/dynamic/units`. |
| `-d`, `--log-hide-date` | `TRAEFIK_LOG_HIDE_DATE` | Don't write the date in the logs (journald already adds it). |
| `-v`, `--verbose` | | More logs, repeat for more (`-vvv` is debug, `-vvvv` is trace). |
| `-q`, `--quiet` | | Fewer logs, `-q` turns them off. |

### Logging

Logs are output to stdout. The default level is error, and `-v`/`-q` change it.

The environment variable `RUST_LOG`, as is common with Rust applications, overrides `-v`/`-q` when it is set. It can
be set to error, warn, info, debug or trace. Setting it without a prefix enables logs for all libraries used by the
application, so it is better to prefix it with `systemd_traefik_configuration_provider=`, e.g.
`RUST_LOG=systemd_traefik_configuration_provider=info`, to only get logs from this application.

## Releasing

Releases are being created using Make and Nix cross compilation. See [./cross-build.nix](./cross-build.nix) and
[./flake.nix](./flake.nix) and [./Makefile](./Makefile).

To release, simply run `make`, which will build static binaries for amd64 and arm64 using musl.

## Testing

Run `cargo nextest run --no-fail-fast` (or `make test`) to get the test report, and `make lint` to run clippy the same
way the pre-commit hook does. CI runs both through Nix (`nix build .#x86_64_test .#x86_64_clippy`).

To run an end to end test, run:

```bash
while true; do sudo systemctl stop sleep.service; sleep 0.1; ! [ -f test/units/sleep.service.yml ] || break; sudo systemctl start sleep.service; sleep 0.1; [ -f test/units/sleep.service.yml ] || break; echo -n .; done
```

This will run until it fails or you press ctrl-c.
